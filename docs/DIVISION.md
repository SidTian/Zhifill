> 项目：**智填 ZhiFill**\

## 一、第一阶段总体目标

当前阶段主要完成 **个人用户场景（Personal Knowledge Base）** 的基础系统搭建与技术路线验证。

重点验证完整流程：

**用户历史资料输入 → 知识抽取 → 知识图谱构建 → 当前任务文件理解 → Agent 推理 → 自动填报（回填下载）**

企业知识库场景作为 **后续扩展**，本期不做。

环境统一：Python **3.12**、Node **20**（见 `docs/ENVIRONMENT.md`）。\
协作方式：契约优先（`packages/contracts` + 各模块 `port.py`），GitHub 可见规划。

***

## 二、系统整体技术链路

```

└─────────┬─────────┘
          │

     ▼         ▼

│ 2.1 知识 │    │ 任务需求表示 │
│ 抽取+图谱│───▶│ + 图谱知识   │

               ┌─────────────┐
```

### 1.3 表格/文档语义理解与任务需求建模

| 项        | 内容                                                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **核心目标** | 将当前任务文件转为结构化语义表示，理解字段含义与填报需求，为 **2.2 Agent** 提供任务输入                                                                                                     |
| **主要任务** | 1. 字段语义识别：不同说法映射统一语义，并与 **2.1 Schema** 实体类型匹配2. 表格语义表示：复杂二维表 → 结构化语义，降低布局干扰3. 字段类型识别与规范化：文本 / 数值 / 时间 / 混合4. 生成 **结构化任务需求表示**：需查询的实体类型与属性，供 Agent 检索与生成 |
| **输入**   | 1.2 的结构/位置结果；2.1 的 Schema                                                                                                                               |
| **输出**   | 字段语义方案结果、表格语义表示、**任务需求表示（TaskSpec）**                                                                                                                    |
| **对接**   | → **2.2**；Schema 对齐 **2.1**                                                                                                                             |
| **阶段成果** | 字段语义理解方案、表格语义表示方案、任务需求表示格式                                                                                                                              |
| **不做**   | 图谱构建；LLM 填报生成正文（2.2）；前端                                                                                                                                 |

### 2.1 知识抽取与知识图谱构建

| 项            | 内容                                                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **核心目标**     | 将用户历史资料转换为可查询 **个人知识图谱**                                                                                                                           |
| **主要任务**     | 1. **设计 Schema**（实体类型、属性、关系、抽取范围）— **全组标准**2. LLM 实体识别、关系抽取、严格三元组生成3. 实体规范化、消歧与融合4. 构建个人 KG，为 Agent 提供知识来源（推荐 LightRAG 或等价方案，与仓库 `modules/rag` 对齐） |
| **输入**       | 1.1 统一表示后的资料；Schema 自洽                                                                                                                             |
| **输出**       | Schema 文档；抽取流水线；可 query 的图谱；入库/删除/更新语义                                                                                                             |
| **图谱更新（硬性）** | 新文件入库须 **增量更新** 节点/关系；同文档更新建议先删后插，避免陈旧事实                                                                                                           |
| **对接**       | ← 1.1；→ 2.2 检索；Schema → 1.3                                                                                                                        |
| **阶段成果**     | Schema 设计方案、知识抽取流程、个人知识图谱 Demo                                                                                                                     |
| **不做**       | 任务文件结构/语义（1.2/1.3）；前端与回填                                                                                                                           |

### 2.2 Agent 智能推理与知识增强生成

| 项        | 内容                                                                                                                                                                                            |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **核心目标** | 连接知识图谱与大模型，完成基于检索、动态 Prompt 与 LLM 推理的智能填报                                                                                                                                                     |
| **主要任务** | 1. Agent 流程：任务分析 → 知识检索 → 信息组织 → Prompt 生成 → 结果输出2. 知识增强检索：图谱 + 向量，按任务需求精准取知识3. 根据 **1.3 任务需求** + **2.1 图谱** 做动态 Prompt4. 知识约束生成：来源限制、格式约束、一致性校验，降幻觉5. 对比 Qwen、DeepSeek 等本地模型（中文、结构化输出、效率、成本） |
| **输入**   | 1.3 `TaskSpec` + 字段列表；2.1 RagPort/图谱                                                                                                                                                          |
| **输出**   | 填写建议（值 / 置信度 / 来源）；Agent 流程与 Prompt 模板；模型选型结论                                                                                                                                                 |
| **对接**   | → 统筹前端预览与回填；**禁止** 将用户确认值默认写回图谱                                                                                                                                                               |
| **阶段成果** | Agent 流程设计、知识增强检索方案、动态 Prompt 模板、大模型选型报告                                                                                                                                                      |
| **不做**   | 原始文件解析；磁盘写回；Schema 终稿（属 2.1，可参与评审）                                                                                                                                                            |

## 四、模块协作关系

| 协作对                | 关系                              |
| ------------------ | ------------------------------- |
| **1.1 ↔ 2.1**      | 1.1 提供统一输入；2.1 按 Schema 抽取并建图谱  |
| **1.2 ↔ 1.3**      | 1.2 结构与位置；1.3 语义与任务需求           |
| **1.3 ↔ 2.2**      | 1.3 输出任务需求；2.2 检索 + Prompt + 生成 |
| **2.1 ↔ 2.2**      | 2.1 提供图谱；2.2 调用知识并推理            |
| **2.1 → 1.3**      | Schema 作为字段-实体匹配标准              |
| **1.2 + 2.2 → 统筹** | 位置（locator）+ 填写结果 → 前端预览与自动回填   |
| **统筹**             | 最终模块整合、API 编排、部署与 Demo 验收       |

### 主数据流（知识入库）

```
用户(前端) 上传历史资料
  → 1.1 统一表示
  → 2.1 按 Schema 抽取并 upsert 图谱（增量更新）
  → 前端展示状态 / 探测问答
```

### 主数据流（填表导出）

```
用户(前端) 上传当前任务文件
  → 1.2 结构解析（位置/表格区域）
  → 1.3 语义 + 任务需求 TaskSpec
  → 2.2 Agent（查 2.1 图谱）→ 建议填写结果
  → 用户预览修改（不回写图谱）
  → 统筹回填写回 → 下载
```

### 建议联调顺序

1. **2.1** Schema 初稿评审（全员对齐）
2. **1.1** 样例资料 → Bundle 稳定
3. **2.1** 图谱可问答
4. **1.2** Word 结构 + locator
5. **1.3** TaskSpec
6. **2.2** 建议填写
7. **统筹** 回填 + 前端 E2E + 部署

### 协作纪律

| 规则        | 说明                                      |
| --------- | --------------------------------------- |
| 一人一主方向    | 只改自己负责目录；跨目录须配对或统筹批准                    |
| 契约优先      | 改 I/O 先改 `packages/contracts` 并 bump 版本 |
| 接口稳定      | 只依赖对方 `port.py`，不 import 对方内部实现         |
| Schema 门禁 | 实体/关系变更须 **2.1** 发起，统筹 + 1.3/2.2 知情     |
| 进度同步      | 阻塞项提前同步统筹                               |
